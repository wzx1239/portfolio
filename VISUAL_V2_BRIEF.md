Do a Visual V2 pass on the existing portfolio.

IMPORTANT:
Do NOT rebuild the site architecture.
Do NOT change the existing 9-project structure, routes, language system, or project data architecture.
This is primarily a visual-direction refinement of the current implementation.

The current version is structurally successful, but visually it feels too much like a quiet architecture/editorial portfolio. It needs to feel younger, more lively, more personal, and more connected to games and interactive work — while preserving the strong alignment, clarity, and recruiter usability.

1. HERO

The current abstract architectural 3D artwork and “Worlds in the making.” composition should NOT define the final identity.

Replace the Hero concept with a media-first showreel system.

For now, create a neutral replaceable showreel placeholder rather than designing another elaborate fake artwork.

The Hero should:
- occupy almost the full viewport
- be dominated by video/media
- have very little UI
- support a future showreel MP4
- hide the main navigation initially
- reveal navigation after leaving the Hero
- allow the user to scroll past at any time
- restart the showreel when returning to the top
- keep any text secondary to the media

Do not invent a new large slogan as the main Hero element.

2. OVERALL VISUAL PERSONALITY

Keep:
- strong grid
- visual alignment
- sharp corners
- restrained UI
- thin lines
- numbering
- indexing language
- generous whitespace in information areas

But make the site:
- younger
- more energetic
- more interactive
- less like an architecture studio
- less beige / muted
- less Swiss-corporate
- more like a personal creative portfolio

Do NOT solve this by adding stickers, doodles, cute icons, gradients everywhere, or random bright colors.

The energy should mainly come from:
- motion
- typography
- image behavior
- scale changes
- transitions
- geometric line systems
- interaction

3. COLOR

Reduce the dominance of the current beige + olive visual identity.

Create a more neutral base system that will work with colorful real project imagery later.

Do not commit the whole website to one strong background palette yet.

Keep category colors subtle:
Game = purple
Architecture = dark/black
Video = pink

Use these primarily as interaction accents, not large background fills.

4. PROJECT DIRECTORY

Keep the three-category structure:
GAME 01–03
ARCHITECTURE 04–06
VIDEO 07–09

Keep all three projects in each category visible together.

Keep images dominant.

However, make the directory feel less like three portfolio cards placed on a page.

Increase the sense of interaction.

On hover, a project should feel activated:
- media can transition from filtered/neutral to full color
- preview video can replace the still image
- project title can subtly move or change scale
- project number / line / arrow can react
- neighboring projects can respond very subtly if appropriate

Do not make the interaction chaotic.

The resting layout must remain aligned and easy to understand.

5. PLACEHOLDERS

Stop designing elaborate fake project artwork.

The current placeholder renders are visually strong enough that they create a false identity for the portfolio.

Replace future placeholder design work with intentionally neutral media placeholders.

The real identity should eventually come from Zixiao’s actual:
- Unreal Engine footage
- game environments
- architectural renders
- video work

Make placeholder media extremely easy to replace.

6. TYPOGRAPHY

Keep sans-serif typography.

Increase personality in display typography and category typography.

Experimental typography is allowed for:
- GAME / ARCHITECTURE / VIDEO
- 01–09
- section labels
- transitions
- selected decorative text

Possible techniques:
- scale changes
- vertical labels
- edge alignment
- controlled rotation
- text moving in response to hover/scroll

But maintain strong visual alignment.

Body copy and metadata must remain conventional and readable.

7. MICRO TEXT

Reduce decorative micro-copy.

Keep small technical/index labels only when they contribute to hierarchy or navigation.

Do not fill empty space with tiny pseudo-editorial text.

Important information should not be extremely small.

8. ABOUT PREVIEW

Keep the basic current layout because its structure works.

However, make the interaction more noticeable.

Create one lightweight interaction using typography + geometry.

Do not turn it into a mini-game.

The positioning sentence is temporary copy, so make it easy to replace.

9. MOTION

Strengthen the motion system.

Create a consistent motion language across:
- section entry
- category headings
- project hover
- image reveal
- navigation appearance
- project opening
- About interaction

Motion should feel responsive and playful rather than luxurious/cinematic.

Avoid excessive slow fades.

Prefer:
- direct movement
- clipping/reveal
- scaling
- sliding
- image transformation
- line movement

Keep animations relatively quick and responsive.

10. PROJECT OPENING

Strengthen the transition from project thumbnail to project page.

The ideal feeling is:
selected project image → expands/transforms → becomes project Hero.

Use the cleanest technically reliable implementation.

11. DO NOT CHANGE

Do not:
- rebuild the information architecture
- remove the 01–09 system
- create a custom cursor
- add background music
- add UI sound
- add a heavy Three.js scene
- create a game HUD aesthetic
- add stickers/doodles
- add random floating decorative objects
- turn the website into an experimental navigation puzzle

Recruiters must still understand the website immediately.

The target balance is:

personal creator portfolio
+
game/interactive sensibility
+
architectural visual discipline

architecture studio website

NOT:

generic UX portfolio

NOT:

frontend/WebGL showcase

NOT:
